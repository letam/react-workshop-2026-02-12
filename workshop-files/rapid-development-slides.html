STATE MANAGEMENT SHORTCUTS

Choose the simplest option that works:

Level 1: useState

Single component state. Start here.

Handles 80% of use cases.

Level 2: Lift State Up

Share between siblings via parent.

Props down, callbacks up.

Level 3: Context + useReducer

App-wide state without libraries.

Only when prop drilling hurts.

Level 4: Zustand / Redux

Complex apps with many stores.

Large teams, complex requirements.

PATTERN: LIFT STATE UP

// Parent owns the state
function App() {
const [items, setItems] = useState([])
return (
<>
<AddItem onAdd={item =>
setItems([...items, item])}/>
<ItemList items={items}/>
</>
)
}

⚠️ GOLDEN RULE

If you're reaching for complex state management early, you might be overengineering. Start simple.

COMMON TIME TRAPS

Patterns that slow you down:

🎨 Premature Styling

"Just need to fix this padding..."

Hours lost on pixels before logic works

FIX: Functionality first, polish later.

🔧 Building from Scratch

"I'll build my own modal..."

Accessibility? Focus traps? Edge cases?

FIX: Use shadcn/ui, Radix, Headless UI.

📊 Over-Architecting State

"Let me set up Redux properly..."

Actions, reducers, selectors, middleware

FIX: useState solves most problems.

⚡ Premature Optimization

"This might be slow with 10k items..."

You have 10 items. Optimize when needed.

FIX: Make it work, then make it fast.

🔐 Custom Auth

"Just need JWT + refresh tokens..."

Security is hard. Really hard.

FIX: Clerk, Auth0, Supabase Auth.

📁 Perfect Project Structure

"features/dashboard/components/ui..."

You have 4 components total.

FIX: Flat structure. Organize as you grow.

MOCK FIRST, INTEGRATE LATER

Don't wait for the backend. Mock data lets you build and test the UI in parallel with API development.

Mock Data Pattern
// data/mockUsers.js
export const users = [
{ id: 1, name: 'Alex', role: 'Admin' },
{ id: 2, name: 'Sam', role: 'User' },
]
Fake API Pattern
// Simulate network delay
const api = {
getUsers: () =>
new Promise(r =>
setTimeout(() => r(users), 300))
}
